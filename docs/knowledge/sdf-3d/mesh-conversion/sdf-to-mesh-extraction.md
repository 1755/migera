# Extracting a mesh from an SDF (isosurface extraction)

This document covers the reverse direction from
[exact-point-to-mesh-distance](./exact-point-to-mesh-distance.md)/
[sign-determination-methods](./sign-determination-methods.md): given an SDF (procedural,
grid-sampled, or neural), produce an explicit triangle mesh approximating its zero level
set. This is needed whenever the final target is a conventional rasterization pipeline,
3D printing, physics engine input expecting triangles, or any downstream tool that
doesn't understand implicit surfaces.

## Marching Cubes: the baseline standard

Marching Cubes (MC) is the foundational algorithm: the SDF is sampled on a regular grid,
and each cube of 8 adjacent grid samples is classified by which corners are inside vs.
outside the surface (256 possible sign configurations, reducible by symmetry to 15 base
cases). For each cube containing a sign change, triangles are generated by interpolating
along the cube's edges between inside/outside corner pairs, using the actual SDF sample
values (not just the binary sign) to place the triangle vertices proportionally closer to
whichever corner has the smaller magnitude — giving reasonably accurate surface
positioning even at moderate grid resolution.

- **Strength**: simple, robust, well-understood, produces guaranteed-manifold output for
  well-behaved input fields, and is the long-standing de facto standard for converting
  distance fields to boundary meshes.
- **Weakness**: vertices are always placed on grid *edges*, which makes it fundamentally
  unable to represent sharp features (corners, hard edges) faithfully — a sharp edge gets
  rounded off unless the grid is refined far beyond what's otherwise needed, since MC has
  no mechanism to place a vertex at an edge/corner interior to a cube.

## Dual Contouring: recovering sharp features

Dual Contouring (DC) takes the opposite approach: rather than placing vertices on cube
edges, it places one vertex *inside* each cube that contains part of the surface (hence
"dual" — operating on the dual grid relative to Marching Cubes), positioned via a
least-squares fit using not just sample values but also **gradient (normal) information**
at edge crossings — which, per
[what-is-an-sdf](../fundamentals/what-is-an-sdf.md), an SDF provides essentially for
free via its own gradient.

- **Strength**: can recover sharp edges and corners accurately, since the vertex position
  isn't constrained to lie on a grid edge.
- **Weakness**: the classic algorithm is not guaranteed to produce a manifold mesh
  (topology can be locally incorrect in ambiguous configurations) and is harder to make
  differentiable/learnable than Marching Cubes — a real consideration for the neural-SDF
  pipelines discussed in
  [neural-and-learned-sdfs](../state-of-the-art/neural-and-learned-sdfs.md). "Manifold
  Dual Contouring" and related variants specifically target fixing the non-manifold
  failure mode.

## Dual Marching Cubes and other hybrids

Dual Marching Cubes (DMC) combines ideas from both algorithms — leveraging Marching
Cubes' robustness/manifold guarantees while recovering some of Dual Contouring's
sharp-feature fidelity. This general pattern (hybridizing the two base algorithms'
strengths) recurs across several more specialized variants in the literature.

## Neural / learnable variants

As isosurface extraction increasingly sits inside differentiable/neural pipelines (a
neural SDF being optimized end-to-end against a mesh-based loss, or a network directly
predicting mesh output), fully differentiable extraction methods matter:

- **Neural Marching Cubes (NMC) / Neural Dual Contouring (NDC)** — learnable variants of
  the classic algorithms.
- **FlexiCubes** — specifically targets making Dual-Contouring-style sharp-feature
  extraction differentiable and manifold-safe simultaneously, addressing DC's classic
  weaknesses in a form suitable for gradient-based optimization pipelines.

This is an active research area because Marching Cubes' hard, non-differentiable edge-
interpolation branching is awkward to backpropagate through cleanly, while Dual
Contouring's non-manifold failure modes are a correctness problem independent of
differentiability — so the "ideal" extraction method for neural pipelines needs to solve
both problems at once, which no single classic algorithm does.

## Practical guidance

| Need | Method |
|------|--------|
| General-purpose, robust, guaranteed-manifold mesh from a grid SDF | Marching Cubes |
| Preserve sharp mechanical/CAD-style edges and corners | Dual Contouring or Dual Marching Cubes |
| End-to-end differentiable pipeline (neural SDF training against mesh loss) | FlexiCubes or another neural/learnable variant |
| Real-time/GPU extraction (e.g. for terrain, destructible voxel worlds) | GPU-parallelized Marching Cubes variants are the most common production choice given their manifold guarantee and simplicity |

## When to dive in

- Converting a baked or procedural SDF to a mesh for rasterization/export → Marching
  Cubes is the safe default; only reach for Dual Contouring if sharp-edge fidelity is
  specifically important and you can tolerate occasional non-manifold output (or use a
  manifold-safe DC variant).
- Building a neural SDF training pipeline with a mesh-based supervision signal → read
  about FlexiCubes/differentiable extraction before defaulting to non-differentiable
  Marching Cubes, which will block gradient flow through the extraction step.
- Extracting meshes at runtime (terrain, voxel destruction) → GPU Marching Cubes variants
  are the standard production choice; see
  [performance-and-production](../performance-and-production/INDEX.md) for the broader
  cost picture of runtime mesh extraction vs. staying in SDF representation.
