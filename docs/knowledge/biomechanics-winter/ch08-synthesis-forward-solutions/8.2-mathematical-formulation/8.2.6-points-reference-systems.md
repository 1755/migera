# 8.2.6 Points and reference systems

> **Source:** Winter (2009) §8.2.6, pp. 208–210 ·
> [open PDF at p. 208](../../../../books/bmcoh/BIOMECHANICS_AND_MOTOR_CONTROL_OF_HUMAN.pdf#page=221) ·
> Up: [8.2 Mathematical formulation](./INDEX.md)

A model is reduced to a **vector network** of two groups of linked lists:
*points*, each given in some reference frame, and *local reference systems
(LRS)*, each with an origin point and an orientation. Every list's first
element is the index of its parent, so walking the links gives every
point's global position. This is forward kinematics over a tree, the same
structure as a skeleton hierarchy.

## Key ideas

- A point has at most 3 DOF in a Cartesian reference system (RS). An RS
  adds up to 3 rotational DOF to its origin's translational DOF.
- "Points" include RS origins, segment COMs, force application points,
  joint centers, muscle insertions and any other point of interest.
- An LRS is defined by its origin point and its orientation relative to an
  already-defined frame (usually the GRS). A point is defined by its RS and
  its local coordinates.
- Construction: pick a stationary point $pt(0)$ and build the **GRS**
  (index 0) there. Define points in the GRS, some of which become LRS
  origins. Define LRSs on those, then points in the LRSs, and repeat until
  the whole model is covered. Every point and every LRS gets its own unique
  index.
- Generalized coordinates appear inside the lists as implicitly
  time-dependent symbols. Everything else is a constant.

## Equations and numbers

$$pt(i) = [\,j,\ x_i,\ y_i,\ z_i\,] \quad\text{(point } i \text{ in frame } j\text{)}\tag{8.10}$$

$$\mathrm{LRS}(j) = [\,k,\ \theta_{1j},\ \theta_{2j},\ \theta_{3j},\ 0\,]\quad\text{(origin at } pt(k)\text{)}\tag{8.11}$$

In 2D: $pt(i) = [j, x_i, y_i]$ and $\mathrm{LRS}(j) = [k, \theta_j]$.

**Sliding-block example** (Fig. 8.2). Block $m_1$ slides horizontally, and
particle $m_2$ slides along $m_1$'s top face, which is inclined at
$\theta$. There are 2 DOF.

```
LRS(1) = [1, θ]                 # frame on m1's slope, origin pt(1)
pt(1)  = [0, q1, 0]             # m1's reference point, in the GRS
pt(2)  = [1, d1 − q2, 0]        # m2 along the slope          (8.12a)
```

To get the contact (normal) force, give $m_2$ a superfluous coordinate
$q_3$ normal to the slope, then cancel it with a constraint:

```
pt(2) = [1, d1 − q2, q3]
0     = q3 − d2                 # d2: m2's COM height above the slope (8.12b)
seg(1) = [1, m1]
seg(2) = [2, m2]                # (8.12c)
```

The segment list `seg` names the COM point and its mass (plus inertia for
rigid segments, Eq. 8.26). The example continues in
[8.2.7](./8.2.7-displacement-and-velocity-vectors.md) (Eqs. 8.12d–g).

## Relevance to migera

The pt/LRS lists are the same thing as migera's bone hierarchy. Each bone is
an LRS whose origin is a point in its parent frame, and FK walks the parent
indices (`src/character/anim/rig.rs`). The book puts the orientation
*angles* in the LRS list. migera stores quaternions, which avoids the
Euler-angle singularities that §8.2.7's zxz matrices carry. The
superfluous-coordinate trick (add a DOF, then constrain it away, to read
out its constraint force) is how a maximal-coordinate engine like avian
exposes joint reaction forces.
